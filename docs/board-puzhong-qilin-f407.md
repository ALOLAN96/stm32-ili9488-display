## 按排针脚号核对的连接

| RESET | 8 | RESET → U1-15 | 公共RESET → MCU NRST-25 |
| WR | 10 | NWE → U1-11 | PD5 / FSMC_NWE |
| CS | 12 | NE4 → U1-9 | PG12 / FSMC_NE4 |
| RS / D/C | 14 | **A10** → U1-10 | **PF12 / FSMC_A6** |
| RD | 16 | NOE → U1-12 | PD4 / FSMC_NOE |
| D0,D1,D2,D3 | 32,30,28,26 | DB0…DB3 | PD14,PD15,PD0,PD1 |

模组侧“ A10 ”是该张图的网络名，不意味着本开发板使用PG0/FSMC_A10；应通过排针14脚追踪到PF12/A6。

## 接口、地址与像素

HW-01 的 U1-38(IM0)、U1-40(IM2)接地，U1-39(IM1)接3.3V，即 IM[2:0]=010。IC-01 §3.2.1、p20表1规定为 MIPI DBI Type B 16-bit，数据线DB15:0。该模组配置应选择 `DRV_ILI9488_DBI_16`；RGB565对应p127图115及注2的一像素一次传输，不能照搬旧Demo的两次拆字节写法。

F407使用NOR/PSRAM第4片选区NE4，基址0x6C000000；16位外部总线使FSMC_A6对应CPU字节地址bit7，因此模板采用命令地址 **0x6C000000**、数据地址 **0x6C000080**。这来自实际排针映射与地址位推导，不依赖旧结构体+偏置技巧。[ST RM0090 §36.4.1、表217/218](https://www.st.com.cn/resource/en/reference_manual/dm00031020-stm32f405415-stm32f407417-stm32f427437-and-stm32f429439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)

旧代码命令地址0x6C00007E也使A6为0，只有RS这一根地址线参与模组选通时属于命令区的另一地址；这里改用对齐的区起始地址明确表达用途。

## 复位与背光边界

HW-02 的RESET含R19=10K上拉、C32=104及复位按钮，并接MCU NRST。屏幕没有单独MCU GPIO复位线，因此port的 `set_reset=NULL`；未来真实panel选择明确的软复位策略。禁止将系统复位线或 `NVIC_SystemReset()` 包装成 Device 的同步复位回调。

软复位不能替代上电所要求的物理复位。IC-01 p298要求：上电时RESX高/不稳需在电源有效后施加硬复位；若保持低电平，电源有效后至少保持10µs。p305/306给出复位脉宽和释放等待；p149、p164/165给出软复位与Sleep In/Out等待。当前120ms切换保护策略与这些约束一致，但是否真正满足供电/NRST波形仍须板上测量。

宿主必须在电源及物理复位前提满足后完成启动等待，再允许 `is_ready=true`。建议本模板集成时从已确认复位释放之后额外等待至少120ms，满足保守启动策略；不能简单用“FSMC初始化返回了”代替屏幕就绪，也不能声称RC标称值证明了上电时序。

HW-01 的U1-33(A)经R4接3.3V，K34/35/36接地，R4数值未标注；P1-3未连入背光。按此图无法通过PB15控制背光或PWM，不提供假定的背光有效电平。若实物PB15确实能控制，需要对应修订图或实测依据。

## 模板实现与宿主职责

新增文件：

- `User/BSP/bsp_lcd8080.h` / `bsp_lcd8080_puzhong_f407.c`：两个固定地址的volatile半字写；每次写后DSB。无GPIO/FSMC初始化、协议或可写运行状态。
- `User/BSP/Ports/bsp_ili9488_fsmc_port.h/.c`：借用持久服务表建立DRV port，逐周期检查就绪/总预算，提供最短等待；不解析像素，不持有源指针。
- `tests/test_boardport.c`：真实port配虚拟时基和原始写周期替身；主机绝不执行MMIO后端。

宿主服务表的 `is_ready` / `now_ms` 必需，`idle` 可空；空时忙等，非空时只能有界让出CPU。时基须持续运行；停止SysTick、关闭相关中断或让idle无限阻塞会破坏时间契约。服务表、context在Device绑定期内有效且表不改写。板级资源启停由宿主唯一所有者负责，port不重复调用MX初始化。

目标固件使用候选配置时加入五个生产C文件（含 `User/Device/ILI9488/drv_ili9488_panel_demo.c`）和三个包含目录：`User/Device/ILI9488`、`User/BSP`、`User/BSP/Ports`。真实MMIO文件限定ARMv7E-M的GCC/Clang编译路径，需选择实际F407目标；不能据此推断支持其他MCU的地址或缓存行为。ARMCC5/MSVC不是本后端已验证工具链。

示意组合顺序（不生成缺参数的可烧录App）：

1. 唯一入口配置时钟、GPIO AF12、FSMC异步非复用16位NE4；根据目标HCLK与数据手册§17.4.1、p325的DBI Type B时序核算ADDSET/DATAST等，不照抄旧数值。
2. 核实供电/NRST前提并完成启动等待，然后放行宿主就绪状态。
3. `BSP_ILI9488_FSMC_MakePort(&persistent_services, &port)`，检查返回值。
4. 选已确认的真实panel，配置DBI_16及软复位；调用Device InitState/Open。
5. App查询尺寸、重绘；总线停用前先Close，停用后撤销就绪；恢复总线不等于恢复屏幕寄存器。

MMIO失败可能成为总线Fault或停顿，port不能伪装成HAL错误，也无法用软件超时打断MMIO/DSB。DSB不会证明屏幕接收了命令。吞吐、阻塞和错误路径都需要实板验证。
